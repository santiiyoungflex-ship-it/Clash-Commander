# AmbiX local vision model training

The manual training workflow builds two independent float32 TFLite models:

1. **Arena detector:** YOLO11n trained on Roboflow Universe
   `clash-royale-data-collection/clash-royale-bhjq1`, version 2 (124 classes;
   4,452 source images; the published model page reports 12,022 images in its
   model dataset).
2. **HUD/card detector:** YOLO11n trained on
   `yolotrain-c7s7v/clash-royale-ut3g8`, version 3 (115 classes, 611 images).
   It includes older labels for cards in hand/next and elixir values.

Both models export at 320×320, float32, without embedded NMS. The Android app
runs them locally and combines arena detections, HUD detections, temporal
consensus, hand-card estimates, elixir estimates and the conservative tactical
engine. It does not execute gestures.

## One-time GitHub setup

1. In the repository, open **Settings → Secrets and variables → Actions**.
2. Add a repository secret named `ROBOFLOW_API_KEY` containing a Roboflow API key.
3. Open **Actions → AmbiX train local vision model → Run workflow**.
4. Keep the default 30 epochs for the arena model. The HUD model uses 40 epochs.

The workflow trains both models on their dataset splits, evaluates each on the
test split when available (otherwise validation), exports TFLite and labels,
commits those assets to `ambix-from-zero`, then runs Android regression tests
and builds an APK containing both trained models.

## Important scope and safety

- Both datasets are published under CC BY 4.0; their attribution is recorded in
  each model metadata file.
- The HUD dataset is small and old. Its card coverage may not include every
  card in the configured deck or current game UI. A missing/uncertain hand card
  or elixir reading causes the tactical engine to abstain.
- Published Roboflow metrics belong to their own hosted models, not AmbiX's
  newly trained weights. Use the metrics generated by the training workflow.
- Neither model is a guarantee of 98% accuracy or a competitive rank.
- Automatic gestures remain disabled. Do not enable unattended gameplay until
  both models are evaluated on fresh Moto e32 captures, card/elixir readings
  and placement coordinates are verified, and the stop controls are tested.
